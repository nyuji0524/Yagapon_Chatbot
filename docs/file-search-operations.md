# File Searchナレッジ品質とbackfill運用

## 文書設計

Discord履歴は固定の1時間単位ではなく、会話間隔・80メッセージ・16,000文字を上限に分割する。
各文書にはチャンネル、カテゴリ、期間、参加者、発言数、元メッセージへのリンクを含める。

File Searchのcustom metadataには次を保存する。

- `source` / `schema`: 取り込み元と文書仕様
- `guild_id` / `channel_id` / `channel_name` / `category`: 所属
- `festival`: 10月1日から翌年9月30日までの矢上祭年度（27thは2025-10〜2026-09）
- `source_type` / `status` / `authority`: 取り込み元、確認状態、根拠の信頼区分
- `start_at` / `end_at` / `start_epoch` / `end_epoch`: 対象期間
- `message_count`: 発言数
- `document_key`: メッセージ範囲から生成した安定キー
- `source_url`: Discord上の先頭メッセージ

回答では最大12チャンクを検索し、grounding metadataからチャンネル・日付・Discordリンクを最大5件表示する。

## backfill

`/backfill` は管理者のみ実行でき、同一サーバーでの同時実行を拒否する。

- `差分更新（推奨）`: チャンネルごとの正常完了カーソルを基準に、前日の0時から再索引する。初回は過去30日。
- `指定期間を再構築`: 30日、180日、365日、または全期間を再索引する。
- チャンネルを指定しない場合、閲覧可能かつ除外設定されていない全テキストチャンネルが対象。

アップロード後は長時間オペレーションが完了するまで待つ。新文書がすべて索引された後にだけ同範囲の旧文書を削除する。
途中で失敗した場合は、その実行で追加済みの新文書だけを削除し、旧文書とカーソルを維持する。
履歴が0件の場合も既存文書は削除しない。

APIでは `POST /backfill` の返す `job_id` を `GET /backfill/{job_id}` で照会できる。
失敗チャンネルと進捗はジョブ結果に残る。

## 本番移行チェック

1. 本番コンテナの `server_config.json` でIT Divisionの `corpus_store_name` を確認する。
2. 既存ストアは削除せず、対象チャンネル1つを30日で再構築して回答と参照リンクを確認する。
3. 代表質問セットで、正答・根拠・最新性・「情報なし」の判定を評価する。
4. 全期間の再構築を実行し、失敗チャンネルが0であることを確認する。
5. 一定期間後に未参照の旧ストアを削除する。削除前にストア名と件数を記録する。

年度別検索、ローカル完全一致検索、利用者評価、管理画面を含む移行順序は
[RAG品質・年度・評価の運用](rag-quality-operations.md)を参照する。
